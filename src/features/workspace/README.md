# Workspace and sessions

`useWorkspaceSessions` owns the workspace sections, the session lists they contain, and the active workspace. It coordinates refreshes, creation, reopening, renaming and closing, optimistic naming, pending UI requests, and persisted workspace, selection, and collapse state. Completed-session indicators last for the current browser tab.

There is no main workspace. Sections are built by `workspace-groups.ts` from persisted history rows, live Pi sessions, and folders the user added explicitly, ordered by newest activity. A live session stays visible before its history row is written. A section is named after its folder basename and qualified by its parent only when two sections share it. `workspacePaths` keeps created or opened folders so a section survives even when it has no sessions left, and its order drives the previous-workspace command. The backend returns up to 30 history rows per workspace.

The active workspace follows the selected live session and falls back to the last one used, which keeps Git, todos, quotas, terminal, prompt templates, and the right sidebar in a stable context while the user browses sections. `App.tsx` receives that path as `workspacePath` and supplies cross-feature callbacks such as resetting workspace-scoped state; it must not duplicate the controller's state.

Sessions are created through `NewSessionDialog`, which reaches the host's native folder dialog through `pickDirectory()`, or from the `＋` button of a section. The dialog is labelled `New session`; recent workspaces remain in the sidebar rather than being repeated in the picker. A section lists its four most recent sessions and reveals the rest through a `Show N more` row; collapsing the section resets it to four. A fresh browser unfolds only the three most recent sections and stores that layout explicitly, so every later launch keeps the collapse state the user left behind; seeding never replaces a layout that already exists. A session selected from outside the list, such as the restored session or a sibling shortcut, reveals the section that holds it once, so the restored workspace stays visible even when it is not among the three most recent; a session created from a section's `＋` button leaves that section's collapse state untouched. Typed paths with completion stay available because a headless host may not provide any native dialog. Workspace paths accept both `~/...` and Windows `~\...`; `directory-completion.ts` preserves the separator style the user typed.

A `Search workspaces` field above the list narrows the sections through `filterWorkspaceGroups`, which matches the section name or full path, case-insensitively, and lists the sections whose name starts with the query first. Searching only filters: a match keeps its collapse state, its small mode, and its sessions. The query is transient component state: it is not persisted, and `Escape` clears it.

Pure list, naming, filtering, and grouping rules live in `workspace-groups.ts`; the sibling-navigation rule lives in `sidebar-sessions.ts`.
